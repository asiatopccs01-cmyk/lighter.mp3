# 2026-10-10 手机优化

优化针对安卓与 iPhone 的小屏、触控和渲染负担，保留连续的 3D 旋转作品廊、粒子、星座光效和镜头转场。

- 发布入口从 2,982,013 字节缩小到约 1,065,442 字节，减少约 64%。音乐改为独立 MP3，点击播放后才下载；隐藏的旧图片延迟加载。
- 手机渲染粒子从 6,500 减到 2,400，像素比例上限从 1 降到 0.85，雕塑三角形从 27,960 减到 15,936。桌面仍使用 16,000 个粒子。
- 手机静止时的环境渲染限制为约 30 帧/秒；滚动、拖动和自动漫游不使用该限制。实际帧率取决于设备。
- 不再每帧读取卡片宽度或更新相同的颜色、属性与布局。镜头稳定后，CSS 3D 卡片停止重复更新；进入阅读页后，背景镜头过渡完成即停止持续 WebGL 渲染。
- 合并尺寸更新，使用稳定的舞台高度计算滚动距离，切换高度和横竖屏时保留浏览进度。
- 修正短屏和窄屏的星座入口、选择框及底部控件重叠；恢复手机动效暂停按钮。
- 选择框采用 16px 字号，返回、音乐和暂停按钮扩大触控区域；添加安全区域间距、阅读页独立触控滚动和双指缩放支持。

验证使用 Chromium 手机尺寸、触控与高像素比例模拟，覆盖 320×568、360×640、390×844、393×852、412×915、844×390，以及桌面回归。通过触控事件检查自然滚动，检查月份链接、音频、阅读页后台渲染停止、暂停、自动漫游、横竖屏及刷新恢复。该环境使用软件 WebGL，结果不代表安卓或 iOS 实机帧率，也不等同于 Safari 实机测试。

本轮 50 项检查全部通过，未记录未处理的 JavaScript 异常。手机镜头静止时的采样记录中，背景继续渲染粒子而卡片属性无重复更新；阅读页过渡稳定后，1.5 秒采样期间背景渲染帧数和属性更新均为 0。

## 电脑版卡片显示修正

窗口尺寸变化时，CSS3DRenderer 将远处卡片设为 `display:none`，这些卡片的 `clientWidth` 为 0。此前尺寸缓存记录了 0，使其重新进入视野时被错误放大。现在在尺寸更新时读取隐藏卡片的响应式 CSS 宽度，同时保留已有有效宽度。

同时将镜头变换应用到每张卡片，保留视口内的父图层，避免父图层越过视点后让 Chromium 的鼠标命中检查遗漏已绘制的卡片。卡片的投影位置、斜转轨迹和颜色保持一致。

本次完成 69 项桌面显示和鼠标检查，以及 16 项手机可见性和原生触控检查。桌面覆盖 1440×900、1366×768、1920×1080，滚轮从 FIRE 浏览到最后一章，窗口缩放和跨越手机/桌面宽度后继续显示与点击；检查均通过。
